# 智能去白边阅读开关

- 整理日期：2026-10-08
- 状态：用户已确认需求方向，作为后续原型与开发评估的依据；尚未开始实现
- 核心需求：普通电子 PDF/干净扫描件四边检测；**固定四侧安全留白（不提供用户留白选项）**；保留 Zotero 原生 Reset Zoom 并实施时验证实例级接管；只新增“适合高度”按钮与“识别边界”开关；L1 六页先抽样建立奇偶基准，L2 停稳 500 ms 后精算当前页与前后三页，L3 固定倍率锚点与 5% 死区，滚动中不自动调倍率或位置；不改原 PDF。
- 产品名称：暂定“智能去白边阅读开关”

## 一句话定义

保留 Zotero 原生 Reset Zoom 按钮、图标、位置和点击回调；实施时验证实例级接管及智能模式下的禁用状态处理。启用“识别边界”时，原生按钮执行内容宽度适应；新增“适合高度”按钮执行内容高度适应。关闭开关时恢复原生页宽/页高缩放。四侧增加**固定安全留白，无留白调节 UI**，不修改 PDF。

## 为什么需要它

部分论文和书籍的页面留白很大。Zotero 原生“适合页宽”按页面宽度缩放，页面内部的左右留白也占据屏幕；文字仍可能偏小。上下白边还会增加翻页间的无内容区域。

用户希望阅读过程中直接获得舒适的视图，不必反复打开设置修改缩放，也不必先用外部工具处理 PDF。

本次确定的方向是“**保留原生 Reset Zoom，智能模式下调整按钮可用状态并接管缩放方法；只新增高度按钮与边界检测开关**”，由一个共享的自动四边检测器为两个原生缩放方向提供参数。Zotero 自带“适合页宽/页高”按整张 PDF 页面而非实际内容缩放；不能把原生整页缩放的按钮简单改名作为产品功能。

## 用户操作与预期效果

| 操作 | 预期结果 |
|---|---|
| 打开／切换 PDF | 保留原生 Reset Zoom，另有“适合高度”和“识别边界”开关；检测开启时先利用六页抽样建立奇偶 L1 基准，再在已恢复的当前阅读页自动应用预测适应，停稳后由 L2 精算，无须点击按钮 |
| 点击原有 Reset Zoom | 边界识别开启：适合实际内容宽度并准确双轴定位；关闭：恢复原生按 PDF 页宽缩放 |
| 点击新增适合高度 | 边界识别开启：适合实际内容高度并准确双轴定位；关闭：按原始 PDF 整页高度缩放 |
| 切换识别边界开关 | 开启后对当前文档自动应用智能缩放，之后跨文档持续生效；关闭时恢复原生入口行为，不修改 PDF 或批注数据 |
| 向后翻页 | 后续页面按同一模式与留白偏好处理，每页使用自己的四边内容边界 |
| 固定留白 | 内容四侧保留统一安全余量，首版无用户可调留白入口 |
| 关闭插件 / 卸载插件 | 恢复 Reset Zoom 原有行为、启用状态与图标；移除插件新增按钮及监听器，不改已有 PDF 数据 |

原有 Reset Zoom 的操作位置和用户习惯保留；原插件开关表示是否采用“实际内容边界”来计算缩放，而不是改变缩放方向。高度按钮与开关需要清晰的中英文 tooltip。关闭开关时，下一次点击缩放使用原生页面边界；关闭开关不必强制立即改变当前正在阅读的位置。开启开关后应自动处理当前页，且后续新开／切换 PDF 时持续自动生效。

## 智能模式默认跨文档生效（2026-10-08 新增）

**只要“识别边界”开关保持开启，打开或切换到任意 PDF 后都自动应用智能阅读，不必再按 Reset Zoom。** 等 Zotero 恢复上次阅读位置并确定当前页 `p` 后，**优先完成 L1 六页全书抽样**；抽样结果建立奇偶基础框后，按当前页奇偶模型自动应用一次预测适应，不提前单独精算 `p`。若 L1 缓存已存在则可直接应用。静止约 500 ms 后由 L2 针对真实 `p` 精算并修正；任何正在发生的用户滚动均不能被自动 zoom/scroll 打断。加载与抽样期间暂时保持 Zotero 原视图，不破坏上次阅读位置。开关关闭保持原生行为；宽/高方向建议继承最近使用方向，默认宽度。

**L1 固定六页抽样，取消此前 6+1 当前页额外优先检测。** 在 25%、50%、75% 三个位置各取相邻奇偶两页，共六页；先依序计算这六页并确定奇偶基准，然后允许启动 L2 局部精算和预读。当前页恰好属于六个样本时直接复用；否则不额外抢在 L1 前面精算当前页。样本六页的原始框本身也写入逐页缓存。抽样过程中只维持当前可读视图，不阻塞 Zotero 本身阅读。

自动应用与原 Reset Zoom/菜单快捷键的接管是两条流程：新 PDF 初始化可能直接写 PDF.js 的 `page-width`，插件必须在位置恢复之后主动启动统一智能缩放逻辑。文件切换、异步分析完成、开关改变时应取消过期请求，不得把旧文档结果应用到新文档。

## 两级检测与顺序阅读预读策略（2026-10-08）

**L1 全书预测（先执行）：** 在 25%、50%、75% 三处分别取相邻奇偶两页，共六页；串行抽样并建立奇数、偶数页两组保守基准。采样完成前不启动 L2 预读；采样完成后未精算页可用奇偶模型预测，已检测的六个样本直接命中缓存。基准只是预测，不代表所有其他页面已精确检测。

**L2 局部精算：** 当前可视中心页稳定停留约 500 ms，才启动本页及前后三页共最多七页的检测。**固定优先级为：当前页 → 后 1 页 → 后 2 页 → 后 3 页 → 前 1 页 → 前 2 页 → 前 3 页。** 按 PDF 实际页面序号计算，超出首页末页的页号不执行。每个目标首先检查缓存，之前计算过的页直接跳过；用户正常向后阅读时主要算未来三页，提高下一页的命中率。

**两个阶段共用单并发队列，但先后有硬顺序：先完成 L1 六页并发布奇偶基准，再开启 L2 当前页及前后三页的预读。** L2 内部按 `p → p+1 → p+2 → p+3 → p-1 → p-2 → p-3` 优先级，越界或缓存命中跳过。用户跳页后更新目标和待运行 L2 队列，滚动时只缓存不调整视图。500 ms 是 L2 队列启动条件而不是每一页等待 500 ms。缓存统一使用绝对原始四边界与质量标记，不存页面位图；切换宽高、窗口变化不重复检测。

## 滚动期间冻结显示，停稳后一次适配（2026-10-08 用户明确）

**滚动时不允许插件自动写入任何缩放倍率或双轴位置**。用户手动滑动、鼠标滚轮连续滚动、触控板滚动时，维持当前 PDF.js scale 和视图水平／垂直定位，不因为奇偶页、L1 预测、L2 精算结果异步返回而自动调整；在途检测可以完成并缓存，但不得更新用户正在滚动的视图。滚动时暂时多白边、少白边或未精确居中都属于正常过渡显示，不以最终页裁切精度衡量。
- 每次真正的用户滚动或换页重置约 500 ms 静止计时；持续滚动不启动新的逐页 L2 检测队列，暂不执行后台重型预读，以优先保护交互响应。暂停或撤销过时待执行任务，允许已完成结果安全入缓存。
- 静止 500 ms 后，**选定一个主要阅读页 p**（可按占屏可视面积，接近并列时沿用上次稳定页，避免临界振荡），优先使用已缓存的 L2 精确框，否则触发当前页检测，再执行后三页、前三页的优先预读。
- 等待精确框的异步过程中保持原视图；结果完成后须再次确认读者仍停在 p、未恢复滚动、检测开关仍开启，才按 L3 固定锚点与安全留白决定是否缩放，最多执行一次该稳定周期的自动双轴定位。插件自己触发的 scroll/zoom 事件不能反复重置用户静止计时或形成自动更新循环。
- **例外**：用户主动点击 Reset Zoom / Fit Height、快捷键、主动切换检测模式，应按用户指令执行；打开或切换文档时，**L1 六页完成之后**对恢复位置的当前页主动应用预测适应（若未发生用户滚动），不需要再人为等待一个 500 ms；L2 精算仍在稳定驻留后执行。
- L1 奇偶基础框只是过渡预测，滚动时不执行逐页适配；最终停稳的当前页以 L2 精确框为准。L2 检测失效时保留原有可读视图或安全回退，而不是以预测框冒充精算。

## 第三级 L3：5% 缩放稳定控制（2026-10-08）

考虑到电子书、简单扫描书籍常见的是奇偶页**版心偏移**而不是内容尺寸显著改变，插件在 L1/L2 获得目标四边框后，需要把缩放倍率和平移定位分开处理：

- **固定缩放锚点，防止连续小幅单向变化累积偏移。** 自动跨页/局部精算更新时，用 L2 精准边界或 L1 奇偶基准与**固定四侧安全留白**计算理想倍率 `S_target`，但始终与**上一次真正应用在 PDF.js 上的倍率** `S_anchor` 比较：`abs(S_target/S_anchor - 1) < 5%` 且本页内容、安全保护余量及必要可见区域检查通过，就**不改变缩放倍率、也不移动锚点**，只按本页四边界修正 X/Y 偏移。不得用上一页的理想倍率或未执行的调整结果作新基准；因此即使连续数页各变化 4%，累计变化跨过 5% 仍会触发。
- 若相对固定锚点的倍率差达到 5%，或虽不到 5% 但当前实际倍率会遮挡文字、侵占必要保护留白，则允许更新到安全的目标倍率；**只有真正写入并确认新的倍率后才更新 `S_anchor`**。Fit Width 以水平容纳为准，允许纵向滚动；Fit Height 以垂直容纳为准，横向内容须能正常滚动到达，不能错误切换成适合宽度。
- **用户主动按 Reset Zoom / Ctrl+0 或 Fit Height**、明确切换适应方向时，可绕过自动死区以精确执行用户指令；防止按钮点击无反应。
- 奇偶页即使倍率完全一致，内容位置的横向偏移仍可能显著不同，因此**缩放不变并不等于沿用上一页偏移**。利用 L1/L2 各自的四边框计算双轴定位。
- **基准初始化与复位：** 新打开 PDF、恢复阅读状态、切换适合宽/高模式、手动缩放、改变视窗大小时，都以实际生效的 PDF.js 数值倍率重新建立 `S_anchor`，而不是沿用旧文档的锚点。L1 奇偶页基准和 L2 精算结果仅决定每页 `S_target`；同一 PDF 视图只维持一个缩放锚点，绝不随奇偶页来回切换。`S_target` 由内容尺寸及固定四侧留白共同确定，正文和必要边缘空间不得被截断。
- 5% 目前定为初版阈值。只抑制不必要的自动倍率变化，不妨碍必要的内容保护或用户明确操作。复杂情况仍采取保守回退，不承诺仅凭抽样预测就能保证所有未检测页文字安全。

## 固定的核心要求

### 1. 识别四个方向的内容边缘

自动判断**每一页**上、下、左、右的有效内容边界，四边分别检测，而不是默认内容对称居中。**首版优先保全所有文字**（含页码、脚注和上标）及简单清晰页面的可见内容，不追求像素级贴边，也不自动处理复杂阴影、重度污染扫描或复杂排版；复杂情况允许用户关闭检测回到原生阅读，不提供手动留白设置。对于纯电子文字文献，允许直接复用字符框作为快速路径；当图像分析可以低成本完成时优先补充图像外框。

**强制要求：支持左右及上下不等宽白边、扫描偏移，以及书籍奇偶页镜像装订白边。** 每页须独立得到 `left/top/right/bottom`，依据所选宽度或高度模式同时计算原生缩放比例和双轴视图偏移；不能只改变缩放倍数，仍把原始 PDF 页边居中。自动四边识别是两种模式的必需前提，不允许固定手工边界或假定对称来替代自动检测。

双栏页面应把两栏及相关图表作为完整内容区域处理；本需求不包含拆栏或重排版。页眉、页脚、页码和脚注默认作为内容保留，不要求自动辨别并删除它们。

### 2. 固定四侧安全留白（无用户设置项）

检测到内容原始四边界后，向左、右、上、下统一向外增加**固定的安全留白**，再据此计算缩放与双轴定位；首版不提供留白调节按钮、滑块或设置。固定数值作为内部算法常量，在原型测量清晰扫描的薄字与数字论文后确定。不得按照紧贴文字的边界直接缩放，不允许空白量随翻页无端变化。

L3 5% 缩放稳定判断必须按**原始内容框＋固定安全留白**核验当前倍率是否仍安全；若内容或必要留白会被遮挡，则允许必要的缩放。缓存仍只存**原始四边框 Braw**与质量信息，固定留白只在显示计算时加一次，不能提前写入边界缓存。只改变阅读视图，不改原 PDF。

### 3. 优先保留原生 Reset Zoom，新增适合高度按钮与识别边界开关

**兼容性约束：** Zotero 10.0.5 原 Reset Zoom 在 `page-width` 时会因 `canZoomReset=false` 而禁用。优先仅包装当前 PDFView 的 `_onChangeViewStats` 状态回调，使 Detect Margins 开启时上报的 `canZoomReset=true`；借此让 React 自己启用原生按钮，不修改 DOM 和 PDF.js 原缩放状态。关闭检测时恢复原判断，并在安装/状态切换/卸载时刷新视图统计。原生 React 按钮的 onClick 已绑定 Reader.zoomReset；若将 PDFView.zoomPageWidth 以实例级代理接管，原生按钮、Ctrl/Cmd+0 与各类菜单均可复用已有调用链，无须重绑快捷键或操作原生 DOM。插件禁用/卸载时恢复统计回调和缩放方法；仅在这一机制实测失败时才尝试隐藏原按钮并原位视觉替换。不得改写 Zotero 安装目录；详见技术验证方案。

**界面只净新增两个控件。** 优先保持 Reset Zoom 完全原生，不隐藏、不复制，依靠状态回调调整可用性，并包装 PDFView.zoomPageWidth/zoomPageHeight 路由到智能缩放算法。只有实例级状态回调无法安全兼容时才考虑原位视觉替换。在识别开关开启时，该按钮执行“适合实际内容宽度”，另外新增“适合高度（Fit Height）”按钮和“识别边界（Detect Margins）”开关。两方向共用四边检测缓存；检测关闭时，原生 Reset Zoom 执行原始 PDF 页宽适应，高度按钮执行原生 PDF 页高适应。

高度模式优先保证当前页有效内容的上下边界（含安全留白）适合阅读区高度；若按高度放大后内容比屏幕更宽，则仍需允许正常横向查看，不能偷偷改成按宽度缩放。横向超出、阅读器滚动限制以及多页连续滚动的稳定性均纳入测试。

### 4. 快捷键与所有原生缩放入口必须同步

用户要求不仅覆盖原按钮，还必须覆盖可以触发原 Reset Zoom/适合页宽的其他入口。插件在 Detect Margins 开启时，要让 **Ctrl+0 / Cmd+0**、View 菜单“适合页宽”、PDF 右键菜单“适合页宽”、内部显式调用 Reset Zoom 均使用与插件按钮相同的智能适合内容宽度；Detect Margins 关闭时全部回到原生页宽行为。
“适合页高”的原生菜单入口也应与插件新增高度按钮共享模式规则：检测开启采用自动内容高度，关闭采用原始 PDF 页面高度。
优先复用 Zotero 原快捷键，不主动改变用户熟悉的键组合；统一接管 PDFView 的缩放动作比逐一覆盖键盘事件更稳妥。
PDF 首次加载时直接赋值 `page-width` 的底层过程不拦截；**检测开关开启时，应待位置恢复、页面就绪后由插件主动执行当前页智能缩放**。特定平台双击缩放可能绕过原方法，单独列为兼容性测试。不修改 EPUB、网页或 snapshot 的 Reset。
禁用/卸载插件应恢复原按钮、菜单、快捷键的全部原生行为。具体 Hook 可行性须在 Zotero 隔离配置实测，不能仅凭源码认定已经完成。

### 5. 只改变阅读视图

使用视图层面的裁边与缩放呈现效果，保留原 PDF 文件和文献数据。文本选择、批注、搜索定位、引用跳转仍应准确。

不生成裁剪后的新附件，不替换原文件。阅读模式如何持久化、是否按文档记忆，在实现前评估；默认不强制改写 PDF 的原生阅读状态文件。

## 首版范围与暂不扩展的功能

首版面向桌面 Zotero 内置 PDF 阅读器，保留现有 Reset Zoom 并新增高度按钮与边界检测开关，同时支持每页四边自动识别、**固定四侧安全留白**及正常阅读操作。检测开启时按实际内容边缘缩放并修正两轴偏移；检测关闭时按原页面边缘缩放。

“适合内容宽度”使左右内容及留白匹配阅读区宽度，纵向可以滚动；“适合内容高度”使上下内容及留白匹配阅读区高度，必要时可以水平滚动。两者都不等于保证全部内容在两个方向同时可见。若后续需要“适合内容整页”，可另做第三种取两轴最小倍率的模式，不纳入本轮。

本轮不扩展到 PDF 导出、翻译、文字重排、双栏转单栏、批量永久裁剪或移动端。扫描件和异常页面的识别效果需要验证；遇到无法可靠识别的页面，应保留原始显示并给出简短提示。

**跨文档记住检测开关及开启后自动智能缩放已确定为产品要求。** 分屏和独立阅读窗口的实际技术支持范围仍须由原型验证决定，不能在未经验证前承诺全部覆盖。

## 论坛证据

这些帖子反映用户对阅读去白边的需求，尚不能据此估计市场规模或付费意愿：

- [PDF Viewer: Feature request: Add option to trim margins](https://forums.zotero.org/discussion/124514/pdf-viewer-feature-request-add-option-to-trim-margins)：2025 年 5 月用户明确希望像 Okular 一样，只在阅读时隐藏页边白色区域，不修改 PDF；2026 年仍有人支持。帖子提出外部裁剪工具作为临时办法，另有用户认为该办法不实用。
- [trim margins when reading PDFs](https://forums.zotero.org/discussion/122950/trim-margins-when-reading-pdfs)：2025 年 3 月用户指出部分期刊 PDF 留白很大，在小屏幕上收起留白能改善阅读体验。
- [Setting the default zoom level](https://forums.zotero.org/discussion/96597/setting-the-default-zoom-level)：补充说明快捷阅读入口的需求；该帖并非四边自动识别的直接证据。

“固定四侧安全留白”和“一键切换”是本次产品决定，不应表述为上述每位论坛用户都明确提出过的功能。

## 已有方案与差异

| 方案 | 已确认能力 | 与本需求的关系 |
|---|---|---|
| Zotero 原生页宽缩放 | 按页面宽度调整显示 | 不等于识别四周内容边界 |
| zotero-pdf-setHorizontal | 在设置页选定缩放和滚动模式，新增 PDF 或打开标签页时自动应用 | 已检查的代码没有四边自动识别及此类工具栏开关 |
| Okular | 阅读时隐藏白边，或框选可见区域 | 可参考的独立阅读器体验；可调安全留白未在本次说明中确认 |
| pdfCropMargins | 自动识别白边，支持调整保留留白，输出裁剪 PDF | 能力相近，但属于外部文件处理工具 |

2026-10-08 检索未确认到完整覆盖“Zotero 内置阅读器、自动四边识别、固定安全留白、一键开关”的现成插件。这是本轮查找结果，不能视为不存在竞品的证明。

## 可行性与维护验证

界面可保持简单，但自动边缘识别和阅读器视图集成尚未验证，不承诺与主题开关相同的维护成本。先验证三个问题：

1. 在正常文字 PDF、双栏论文及含图表／公式页面中，能否完整识别内容边界，且保留留白？扫描件、背景色、扫描噪点、旋转页与空白页能否可靠处理或回退？
2. 视图裁边后，批注位置、选字、搜索跳转及链接跳转是否仍准确？关闭后能否恢复视图和阅读位置？
3. 能否通过可维护的阅读器接口实现，并避免翻页卡顿与反复分析？默认优先本地处理，不要求用户另装 OCR、Python 或外部服务；具体识别方案在原型阶段选择。

如必须大量改写阅读器内部结构，或无法保持批注与原页坐标一致，应重新评估实现方案和首版范围。

## 验收标准

- 大白边 PDF 开启后，四周多余留白明显减少，内容更充分地利用阅读区域。
- 固定四侧安全留白生效，内容不会紧贴边缘或因拟合而被截断。
- 翻页后按各页内容处理，不错误复用上一页边界；空白页及低置信度页面可正常阅读。
- 字、图、公式、脚注和页码在默认保守识别下完整保留。
- 一次点击开启，再次点击恢复；操作无需进入完整设置窗口或重开 PDF。
- 开关切换、缩放及翻页前后，选字、批注、搜索和跳转保持正确。
- 原 PDF 文件字节不变，已有文献数据与批注数据不被改写。
- 禁用插件后恢复正常阅读，清理界面、监听及缓存资源。
