## F01（P1）：横向人工滚动被停稳自动居中覆盖

- 位置：`src/runtime.js:109,137,223`。滚动会经 `input()` 重排 500ms 计时，`refine()` 在停稳后经 `apply()` 总是重新设置 `container.scrollLeft`，没有保留用户主动横向浏览的意图。
- 影响：在 Fit Height 模式，宽图/宽表允许横向滚动，但用户把页面向左/右移到需要观察的地方并停止后，插件可能把它拉回内容居中。这不是用户点击 Fit Height 主动重新适应。
- 无修改源码的独立 Controller mock 复现：设 Fit Height 且缩放无需改变，人工设 `scrollLeft=240`，模拟用户输入/停止 600ms，再执行当前页自动 `apply()`；结果 `scrollLeft=255.813953...`，**被插件改写**。实际变更量随页面、窗口和版心不同而变化。
- 修复方向：区分用户水平滚动和普通垂直翻页。用户主动移动 X 后可冻结自动 X 对齐，直到切页、显式按适应按钮或模式变化；L3 继续按规定控制缩放，不能用滚动静止作为重新覆盖用户水平位置的充分条件。
- 回归：Fit Height 宽图分别手动拖到最右和最左，停稳超过 500ms 应继续保持用户看到的位置；垂直翻到另一页仍可按新页自动调整 X。

## F02（P1）：低对比度扫描页边文字可能丢失

- 位置：`src/core.js:80-103`，扫描墨迹判定要求像素 RGB 最暗分量 `<235`；`src/core.js:6` 固定安全余量 8 单位。扫描图没有 PDF 字符几何时，`getTextContent` 无法补救漏检。
- 无修改源码的像素测试：80×80 白底，正文黑字区 x=22..60/y=15..65，页面左侧有一处灰度 238 的浅文字点 x=1/y=40。当前 `inkBox` 返回左边界 21，`safeBox` 扩展后仍从 x=13 开始，**x=1 的浅字被排在安全显示框之外**。
- 这不是“灰字只是看不清”的数学保证；当前阈值确实允许在扫描页面上裁掉像素上存在的浅色文字。是否构成实际用户场景必须用更多真实扫描件确认。
- 修复方向：扫描路径引入低对比度风险检查与保守回退（而非一味全局降阈值引入噪点）；增加灰字、泛黄底、压缩噪点/浅色图表的回归样本，并验证固定 8 单位边界的安全性。

## F04（P2）：测试覆盖与性能界限

- 目前集成 Zotero 是 **10.0.6**；manifest 声称最低 **10.0.5**，但本轮没有在 10.0.5 运行原生按钮/缩放回归。macOS、Linux、物理触摸板惯性、右键菜单实际操作和复杂扫描也仍未验证，文档已有标明。
- `src/runtime.js:267` 对每个新页面无论是否存在电子文本，都进入低清 PDF render 和像素复制；目的是保护文字框之外的图表，因此并非错误，但不是“已有字符框时零重绘”的极致快路径。若未来要优化，应先比较真实有图页的漏检风险与节省耗时。
- 现有进程树采样最大约 1.9 GiB 包含整个 Zotero 渲染/多视图，**不能归因于插件本身**。性能目标建议加“常见百页 PDF 连续浏览、长会话”的额外基准。
