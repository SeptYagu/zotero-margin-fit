# MarginFit 0.1.3 性能优化实施记录（2026-10-08）

状态：**本地开发版，尚未发布**。公开 updates.json 仍指向正式 0.1.2。没有操作正式 Zotero 文献库。

## 实施内容

1. src/core.js / Session：新增 noteActivity、waitForQuiet。用户持续滚动时允许在途页面分析安全完成，但在下一页低清检测启动前等待滚动停止约 500 ms；L1 六页始终先于 L2 前后页分析。
2. src/runtime.js / Controller.input：wheel、scroll 等重复事件立即使失效令牌 epoch 更新，但昂贵的可见页、DOM 几何计算改为约 75 ms 合并一次；切边 OFF 时直接跳过几何分析。
3. 用户主动按 Fit Width/Height 时，可通过 allowExplicitRequest 越过后台空闲等待，避免显式按钮被新冷却机制拖慢。保留先 L1 再 L2 的既有要求。
4. toggle、close 时清理合并事件定时器；保留关闭/卸载可逆行为。

## 同倍率、无新检测的滚动热路径对照

| 指标 | 0.1.2 旧版 | 0.1.3 开发版 |
|---|---:|---:|
| wheel+scroll 事件 | 约 296–297 | 约 296–297 |
| ON + 原生倍率：page() 可见页读取次数 | 296 | 48 |
| ON + 智能倍率：page() 可见页读取次数 | 297 | 52 |
| ON + 原生倍率：输入回调累计耗时 | 80 ms | 16 ms |
| ON + 智能倍率：输入回调累计耗时 | 90 ms | 18 ms |
| OFF：page() 可见页读取次数 | 约 296–298 | 0 |

ON 时可见页几何读取减少约 82%–84%，输入同步热路径时间减少约 80%。**不能把它解释为 Zotero 总 CPU 已减少 80%。**

模拟方法：Windows Zotero 10.0.6 隔离配置，同一 24 页测试 PDF、相同缩放倍率、每组约 140 次模拟滚动，无新页面检测任务。

## PDF 已渲染画布复用：经过验证，暂不启用

一次性 probe 使用 tests/canvas-probe.js 在真实 Zotero 10.0.6 中检查 pageView canvas。可见第 8 页渲染完成（renderingState=3）时，在 page DIV 内存在至少两个 canvas，示例像素尺寸为 768×1023 和 2163×1194；而其余被 L1 抽样的非可见页面往往无任何可复用 canvas。
因此现阶段**不能简单读取 pageView.canvas 的单个画布代替原来的完整页面渲染**：可能是分片渲染、特殊主题或不完整内容，误用会丢文字、图表和边缘细字。保持现有低清渲染路径与安全回退，待有可靠的完整页合成与墨迹结果比较测试后再尝试。

## 0.1.3 验证

- 本地 Node 单元测试：30/30 通过（原 26 项 + 新增 4 项）。新增 L1 延后检测、显式 Fit 解除等待、滚动事件合并、关闭状态免几何查询。
- 隔离 Zotero 10.0.6 集成检查：70/70 通过。保留原生 Reset Zoom、L1/L2、5% 锚点、滚动冻结、阅读位置、真实 PDF/批注安全与卸载还原。
- npm run build 生成 dist/zotero-margin-fit-0.1.3.xpi。未发布、不推 GitHub release、未更改已发布版本的更新源。
- 首次打开时间和 L1 六样本 wall-clock 会受设备负载、额外滚动等待影响，本轮 0.1.3 集成测得 L1 约 1.63 秒、从附件导入到首次适配约 8.04 秒；与历史单次值无法直接做严格性能退化归因。注意真实用户阅读流畅度和首屏等待之间的取舍。

## 尚未解决的性能根因

本次受控测试中，智能内容宽度倍率约为原生页宽的 1.94 倍，相同区域画布像素面积理论约增至 3.75 倍。即使关闭插件但维持该倍率，Zotero 也必须承担更高原生画布渲染开销。这是无法靠事件节流直接消除的部分。
每个未检测页面仍可能重复执行低清 page.render() 以保护真实图表与扫描笔画；本轮通过滚动暂停减少与用户交互的竞争，未减少每个新页面实际需要分析的 CPU 工作总量。

## 下一步验证

用用户观察到的“切边开启时 CPU 达 20%–25%”作为体验基线，对同一真实 PDF 运行：相同倍率 ON/OFF、冷页滚动与暖缓存滚动、不同的真实屏幕滚动速度及 GPU 进程采样。只有完成该对比，才能对整体 CPU 是否显著改善下结论。
0.1.3 源码仍属开发状态；建议在真实桌面使用样本上再次检查后再发布和更新公开 feed。
