# MarginFit 0.1.4 — strict text fast path + persistent boundary cache

Date: 2026-10-08. Status: local development candidate; NOT published. Public automatic update feed remains at 0.1.3.

## Implemented

- src/core.js: detection algorithm version 2; a strict PDF.js OPS allowlist for pure-text pages, rejecting vector paths, images, shading and unknown operators.
- src/runtime.js: if text geometry is reliable, the operator list contains only approved text operations, and the page has zero PDF annotations, skip a second low-resolution page render. Otherwise run the existing conservative raster detector.
- Empty-text scans go directly to raster without a needless operator-list read.
- src/persistent-cache.js: profile-local JSON in marginfit-boundaries, containing only validated absolute page boxes, dimensions, rotation, quality and version; never text or images.
- Cache identity: PDF.js fingerprints, page count, size and last-modified timestamp of local source when available; schema and detection version are validated.
- Session waits for cache loading before L1; previously measured L1 and L2 pages are not re-rendered. Writes are debounced and merge across reader instances. Maximum 3,000 stored pages per PDF.
- Added synthetic pure-text fixture, distinct pause-test PDF, cache unit tests, and real Zotero fast-path/reopen tests.

## Verified

- Real Zotero 10.0.6: pure-text pages skip the low-res canvas entirely (rasterBytes=0). Vector graphic, scanned page and illustrated real-paper test still run the raster detector.
- 24-page document: first open detects six L1 pages; re-opening the same PDF hits six persisted entries and performs zero new L1 renders.
- Same-file cache keys include actual file size and modification timestamp when obtained from the Zotero attachment.
- Existing 70 integration cases pass; revised OFF-during-L1 fixture avoids accidentally warmed cache.

## Performance and constraints

- Benefit: lower CPU on confirmed pure-text pages and near-zero detection work on previously cached pages after reopening. No claim that overall CPU falls by a fixed percentage.
- Native high-zoom PDF.js rendering remains costly. Complex illustrated PDFs still render a low-res analysis canvas; operator-list inspection may add overhead on complex pages.
- Disk cache is local to the Zotero profile and can be deleted safely. Global cache-directory pruning is not yet implemented.
- Cache keys strongly mitigate stale results, but cannot cryptographically detect a PDF replaced with identical fingerprint, file size and modified timestamp.
- Existing 8-unit padding, 500ms idle, 5% deadband, original Reset Zoom and strict no-PDF-modification policies remain unchanged.

## Validation (isolated Zotero profile)

## Suggested release gate

Verify actual CPU on a long document under (a) cold scans, (b) warm cache, (c) pure text, (d) illustrated paper/score, each at the same zoom factor; test annotated PDFs. Then decide whether to publish v0.1.4.
