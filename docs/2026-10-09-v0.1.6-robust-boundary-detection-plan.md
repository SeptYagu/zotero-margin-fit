# MarginFit 0.1.6 — 斜向稀疏采样与二维稳健边界（正式开发方案）

日期：2026-10-09
状态：方案已确定，**尚未实现、验收或发布**
基线：已发布的 MarginFit 0.1.5 / Zotero 10.0.6
用户目标案例：音乐理论书第 76 页，左下角独立页码 76、下方 Chapter 4、正文及例 4.14/4.15 乐谱
工作原则：新路线为唯一主动实施方案；先前其它扫描算法保留在文末备选研究档案，不作为 0.1.6 的并行任务。

## 一、最终确定的主路线

**缓存命中 → 已验证的 PDF 结构快速路径（能安全跳过渲染则跳过）→ 必须检测图像时仅一次低清渲染 → 默认约 25% 斜向交错采样 → 周期性改变采样相位 → 二维主体边界支持度 → 分轴拟合＋原有安全留白 → 低置信度时有针对性加密或回退。**

核心决定：

1. 主算法采用 **4 像素步长、每行错位的斜向稀疏采样**；首选目标采样占比约 25%。在数据证明需要时才提高到约 33%（3 像素步长）或补扫局部。不默认对候选矩形外侧进行完整逐像素核验。
2. **周期性相位变化**用来减轻采样轨迹与某一倾斜方向长期平行造成的漏检。规律必须确定、可重复、可测试；不把它当成完全消除盲区的数学保证。
3. **二维置信度**综合横向延伸、纵向分布、主体连续性、局部边缘突出、可用的 PDF 文字几何与 L1 奇偶页样本。不能单靠一个最外侧采样像素、单一百分位或“细线不重要”来裁边。
4. **完整扫描不再是默认动作**，只作为低置信度／特殊页面的安全回退及离线测试基准。此前 1/8 环带、四方向独立、稀疏后全量外侧验证等路线暂不开发。
5. 不改 PDF、原生页面/文字/批注层、不增加整页渲染次数，不改变现有安全留白、500 ms 停稳与缩放/位置保护。
6. **置信度高才允许收紧拟合范围；否则可增加局部采样，再不可靠则回退现有完整检测。** 追求真实阅读中安全、稳定的结果，而不是声称稀疏采样对所有图案都与全量扫描严格一致。

## 二、为何采用斜向交错、而不是固定水平采样

低清画布坐标为整数 x、y。主实验取 stride = 4，并为每行选择唯一采样相位：

```js
const stride = 4;
const phase = phaseForRow(y); // 由固定小周期变化，不依赖随机数
for (let x = phase; x < width; x += stride) {
  samplePixel(x, y);
}
```

- 基础斜向错位可从 `phase(y) = y % 4` 开始；相邻行的采样列逐次右移，使足够长的**水平线**每行有机会被采中，较长**竖线**跨行也会被采中。
- 但当线与基础轨迹平行时，可能存在整条线恰好落在间隙的周期性混叠；因此测试例如**每 16 或 32 行变化一次附加偏移**，也可以比较非线性四相位排列。它们仍保持每行约四分之一列的访问量。
- **必须承认**：这种采样不是严格无损的；相位变化也不能从数学上保证所有 1 像素斜线、孤立符号被检测到。实际使用通过支持度、文字几何、8 PDF 单位的边缘留白以及必要的回退控制风险。
- 采样固定在实际渲染画布坐标上，旋转、横向页面、不同宽高仍需保持行为稳定；PDF 坐标中的留白距离需要正确换算到低清像素，不能直接把 8 PDF 单位误当 8 像素。
- stride = 3（约 33%）是实验参数，不作为第二套产品算法。周期长度、相位序列、分桶尺度和置信阈值都应根据阴性样本测试定下来，不能只凭直觉确定。

预期单次内存访问量约为 W×H/4，**不是** PDF.js 渲染时间、RGBA 拷贝量或 Zotero 总 CPU 一定下降 75%。

## 三、边界数据与二维置信度

对每页区分：

- `sampledBounds`：稀疏采样中发现的墨迹范围；**是估计，不得伪称完整原始极值**。
- `fullBounds`：只有在已经执行原完整扫描、或可证明完整的 PDF 几何检测时才有严格意义；与 v0.1.5 的 `raw` 语义分开，防止缓存将不完整框误认为无损结果。
- `bodyWidthBounds`：正文、谱例、图表等主要内容支持的左右拟合边界；由二维支持度及附加证据决定。
- `heightFitBounds`：第一阶段继续使用足够保守的完整上下边界／安全估计，不主动剔除页码、Chapter 4 等页脚。
- `confidence`、`evidence`、`fallbackReason`：数值化描述证据及其来源；缓存须记录算法版本和数据质量级别。

二维支持度至少考虑：
- **横向支持**：在采样格点上跨多少列、多少水平分桶连续出现可靠墨迹，避免将较长乐谱线条当成孤立噪点。
- **纵向支持**：在多个高度分开的行/行桶中有多少证据支持左右外缘，避免单独页码 76 只凭极端 x 值决定全页宽度。
- **区域和跨页支持**：正文与乐谱的成组分布、边缘突出区域与正文的距离、奇偶页版心；如可靠 PDF 文字框与 L1 页码规律已知，则直接纳入判定。
- **完整性保护**：图形线端、谱号、附注、小节号、脚注、表格、插图题注、批注等虽可能稀疏，仍属于重要内容。二维算法需综合短线与长线支持，不得单纯丢弃“只有少数行”的全部内容。

可使用小型横纵直方图／行列分桶、局部稀疏连接关系和候选区统计。不要构造完整尺寸的第二张图，不运行 OCR，不在每次滚动事件中重算。初始置信度阈值只是待测试参数，不是先验真理。

### 3.1 横向与纵向适配独立

- **Width Fit**：只有置信度充分时，孤立左下角页码 76 不参与正文左右宽度；真正外伸的谱线和图表仍参与。
- **Height Fit**：维持页脚 Chapter 4、页码等所要求的纵向留白与可见性，暂不追求删去下边缘。
- 如果稀疏证据不足以判断上下边界，就进行额外采样或保守回退；不能把未采到的像素当作确定空白。
- 留白仍为已发布插件的 **8 PDF 单位**，只能加一次。横纵坐标变换、实际 Fit Scale、选区、批注、阅读锚点需一致，原 PDF 内容永不修改。

## 四、置信度不足时的回退与性能边界

默认不执行“候选框外侧全部补扫”。推荐的运行顺序：

1. 对已有缓存直接命中；严格可信纯文字页复用 v0.1.5 快速路径。页面结构分类如果不可靠/过贵则直接走一次低清渲染。
2. 对需要图像的页面执行一次约 800px 最长边低清 `page.render()`，之后按 25% 斜向错位模式只访问采样点。
3. 根据二维支持度和已知文字/奇偶页几何生成候选原始边界估计、主体 Width Fit 与保守 Height Fit。
4. 若信号弱、候选只有少数孤立点、存在不寻常线向/混叠、扫到边缘密集背景、版式非连续、细谱线或批注冲突，则先在**必要的候选区域**提高采样密度。
5. 局部追加仍无法建立可靠边界时，执行已有完整扫描并恢复完整保守裁边；这是低置信度回退，**不是每页默认第二遍扫描**。
6. 把检测方式、置信状态、实际访问比例、回退原因及最终适配框写入版本化缓存；下次打开无需重新扫描。

与当前 0.1.5 行为比较，低置信度回退允许增加少量成本，但不能在大量复杂页面上“先读 25% 再经常全扫”造成系统性退化。应统计回退率并动态决定扫描模式是否值得使用；不能无条件把 25% 先验采样强加于明显低收益的页面。

**性能测量分账**：
- PDF.js 低清渲染 `page.render()`
- `getImageData()` 与跨隔离域 `cloneInto()` 的完整图像读取/拷贝
- 稀疏点读取、二维支持度、局部补扫、保守回退
- 持久缓存加载和更新、完整 detect wall-time
- 用户实际放大后的 Zotero 原生绘制 CPU/GPU 与内存（单独比较）

即使 JavaScript 只访问约 25% 像素，若前面的 render/getImageData/cloneInto 不变，整个检测的加速可能有限。只在独立验证后考虑 ROI 数据传输优化，不让其成为本版开发主任务。

## 五、必须包含的测试

以有人工真值的测试页为准，不以“首次识别到了更多墨迹”判定正确：

**正例**：第 76 页形状相近的文字＋乐谱图例＋页码 76＋Chapter 4；页码在左右页脚交替的书页；真实电子文字的 v0.1.5 页码正确排除案例。

**必须保留的反例**：五线谱与谱号、细连线和短符号、长图表/箭头、表格、脚注、章节标题、双栏版式、低对比度扫描、暗色背景、斜扫、旋转页、批注跨出正文、页码重启和边界附近的合法内容。

**特别的混叠压力测试**：
- 恰好与基础斜向采样轨迹平行且落在空相位中的 1 像素斜线；长度 4/16/32/64 px，检查周期相位切换是否降低漏检风险。
- 只有 1–3 像素宽的细线、单个乐谱记号、极短孤立线、处于相邻采样点之间的小图表标记；必须记录采样漏检，不能因统计平均良好而隐去。
- 0/90/180/270 度旋转、页面宽高奇数、图框边缘与行/列桶边界重合。
- 人为构造信号不足但又能误导置信度的页面；期望正确回退，而不是盲目放大。

评价必须分别给出：
1. 本应保留的重要内容被排除的数量及严重程度（优先级最高）；不允许把重大漏谱线/正文作为可接受优化。
2. 正文 Width Fit 的改进、Height Fit/页脚的保持；第 76 页案例须通过**真实 Zotero 缩放**验证，不止是 JS 候选框。
3. 斜向 25%/33% 与 v0.1.5 全图扫描结果的差异，产生差异的像素结构，安全余量能否实际覆盖。
4. 各类页面首次扫描耗时、额外分配、实际访问比例、局部补扫/全扫回退比例、总 detect 时间及内存。
5. 含 8 PDF 单位安全留白后，所有正文、谱例、图表、脚注及批注仍处于可访问/正确坐标的位置。
6. 既有单元测试（至少 47 项）、Zotero 阅读器 70 项、页码与缓存 18 项及新增测试全部通过；独立 profile，不触碰正式 Zotero。

实测通过前，不宣称该稀疏算法在所有 PDF 上等价于完整扫描，也不宣称 Zotero 总 CPU 一定下降 75%。

## 六、开发阶段（0.1.6 唯一主动执行清单）

**S0 — 固定问题与性能基线**：取第 76 页真实 PDF 检测数据（如源不可得则先做清楚标注的合成 fixture）；确认左右边缘确因页码被污染；保存 v0.1.5 完整扫描结果及缩放倍率；构造错位采样的压力测试集。

**S1 — 斜向错位采样原型**：实现每行约 1/4 像素、相位错位的纯算法原型；比较相位切换周期/非线性相位序列及 stride=3/4；记录访问数、未命中细线和 CPU，不修改生产裁边默认值。

**S2 — 二维支持度与高置信主体裁边**：实现横纵分桶、孤立突出识别、文本几何与 L1 奇偶页辅助；以误排正文/谱例为最高风险，支持不足时局部加密或保守回退；引入横纵分轴的适配框。

**S3 — Zotero 真实适配验证**：测试第 76 页型场景实际 Width Fit 放大、Height Fit 保留 Chapter 4、文字选择/批注坐标、分屏、旋转、滚动锚点；与 0.1.5 精确对照，检查实际意外裁剪。

**S4 — 缓存和端到端性能验证**：算法及缓存版本升级，按低置信度/覆盖度持久化已验证的边界，区分 estimated/verified；冷/热缓存和同倍率 A/B，明确渲染、数据复制、采样、支持度、回退耗时。低收益配置不启用。

**S5 — 完整验收与交接**：全部测试和安全审查、构建 0.1.6 本地 XPI、记录失败实验与未解决边界。未经单独发布决定，不创建 0.1.6 Release、不改 `updates.json`。

执行规则：后续获准开始实施时，每阶段先完成/验证，再 Git commit 和 push，重读此方案与最新交接后继续。失败的相位设计或置信策略保留记录并回退，不把实验性效果包装成保证。

## 七、保留但暂不研究的历史备选

以下仅为技术档案，**不是 S0–S5 的任务**：

- **A — 全图一次扫描＋行支持度**：最可靠的 v0.1.5 参照与低置信度回退；之前曾计划用作主算法，现被斜向稀疏扫描替代为主实验。
- **B — 1/8 同心环带**：第一圈 43.75%、第二圈累计 75%、第三圈 93.75%、第四圈 100%；不能由第一圈页码推断正文已确定。暂不实施。
- **C — 四方向独立内推**：能在覆盖外缘带时数学上确定原始墨迹极值，但无法独立判断主体与孤立页码。暂不实施。
- **D — 稀疏后候选框外全区域补扫**：可保证原始外框数学完整，却抵消部分省像素收益；不作为默认，也不在本版单独开发。
- **原生画布复用／ROI getImageData／全面矢量几何替代渲染**：作为以后可能的独立研究；本版只沿用已验证的纯文字页免渲染流程，不强制扩展所有 PDF 类型。

以上研究记录也可从此前的 Git 提交 `73970e5`、`22dcc78`、`95e4551` 查阅；本文件以**第一节“最终确定的主路线”和第六节 S0–S5**为当前执行依据。

## 八、最终决策

**固定：斜向交错的约 25% 像素采样＋周期性相位变化＋二维边界支持度＋8 PDF 单位安全留白＋低置信度时局部加密或完整回退。**

不再并行比较四套产品扫描算法。首先集中验证：这条路线能否在尽量少访问像素的同时，真正解决第 76 页左下角页码造成的左右宽度过大，而且不会漏掉乐谱、图表和脚注。原始完整扫描继续用于对照和安全回退。

特别区分“25% 采样率”与“完整内容无损保证”：前者是可测的成本目标，后者只能通过限定场景下的置信度、反例和必要回退来提高可靠性，不能无条件声称成立。
