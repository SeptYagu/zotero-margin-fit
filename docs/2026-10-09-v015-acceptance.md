# MarginFit 0.1.5 — 最终验收记录

日期：2026-10-09
测试目标：开发版 0.1.5，Windows Zotero 10.0.6，**独立 profile / 独立 Zotero 数据库**。
状态：**功能验收通过；整机 CPU 降幅没有足够证据保证；正式发布尚未执行**。

## 一、阻塞故障定位与修复

- 先前隔离测试总在 Firefox/Zotero 的 headless SWGL 图形合成器阶段不稳定，远程调试器可能超时。
- tests/run-integration.ps1 增加 -Windowed（仍以隐藏进程+独立 profile 启动），避开 headless 渲染问题。package.json 的 Windows 集成/专项测试现在默认使用此模式。
- 调试器 ACK 偶有丢失，即使完整结果文件已写入且包含 70 项通过检查。测试启动器现在在 ACK 失败后继续检查独立 result.json；**只有 result.json 确认 passed=true 才能判定通过**；超时/结果缺失/检查报错仍失败。这样避免错误的测试失败报告。
- 原始已打开的 Zotero 正式进程（当时 PID 18468）从未停止；不修改真实用户文献库和 PDF。

## 三、0.1.4 vs 0.1.5 性能对照

**受控条件**：同一生成的 24 页 asymmetric-book.pdf，真实 Zotero 10.0.6，手动设为相同缩放倍率，已预热页面边界，140 次合成 wheel+scroll，每组约 296–298 个输入回调，六场景 ON/OFF/native/smart 轮替。

倍率：原生宽度 currentScale = 1.17125；智能内容 currentScale = 2.26650943。高倍本身会增加 PDF.js 原生渲染成本。

| 项目 | 0.1.4 | 0.1.5（优化后） |
|---|---:|---:|
| ON + 原生倍率：滚动阶段页面几何读取 | 约 46 次 | 0 次 |
| ON + 智能倍率：滚动阶段页面几何读取 | 约 62 次 | 0 次 |
| ON + 原生倍率：同步输入回调累计 | 约 10 ms | 约 15 ms |
| ON + 智能倍率：同步输入回调累计 | 约 17 ms | 约 25 ms |
| ON + 原生倍率：输入+几何累计 | 约 28 ms | 约 15 ms |
| ON + 智能倍率：输入+几何累计 | 约 46 ms | 约 25 ms |

期间发现一个 0.1.5 回归：原本每次滚动事件都取消/重建定时器，导致输入回调 40–50 ms。验收时改为单个计时器定期检查 epoch，避免逐事件频繁分配；修复后通过新增确定性虚拟计时器单元测试与完整 Zotero 回归。

**Windows 外部进程树 CPU 抽样（稀疏、仅方向性）**：
- 0.1.4 原生宽度 ON/OFF 约 0.35–0.43 核当量；智能倍率 OFF 约 0.87、ON 约 1.00。
- 0.1.5 原生宽度重复 ON/OFF 约 0.28–0.35；智能倍率 OFF 约 0.94、ON 约 0.89。
- 两版本高倍率下均在约 0.9–1.0 核当量区间，差异不具备统计学说服力。模拟滚动耗时和样本密度受原生渲染/机器负载影响明显；**不能宣称整个 Zotero CPU 已降低某个固定百分比**。
- 更明确的局部收益：P1-A 无损低分配文字边界计算、P2-A 缓存 dirty 页批量写入、P2-B 连续滚动期间 DOM 几何读取归零；P1-B 文档级 raster-first 因数据不足仍不启用。

## 四、保留限制与验收判断

- 0.1.5 页码排除仅在无批注的**严格纯文字页**、跨页规律得到足够 L1 证据时启用；扫描件、乐谱与混合图形继续保留页码（优先防止错删可见内容）。电子页码功能已验收，不等于所有扫描页都能排除页码。
- 不对 macOS/Linux 兼容性宣称已验证；未在长期实际阅读中完成用户主观体验与大型私人乐谱库 A/B。
- GitHub 正式 Release 与 updates.json 在此次验收阶段不修改，当前公开版仍为 0.1.4。0.1.5 的本地 XPI 已经构建。
- **功能验收：通过。性能路径优化：局部收益明确、整体 CPU 非劣仍有有限证据；可以考虑候选发布，但发布应另作明确决定。**
- 同倍率用户真实设备 CPU 20%–25% 的个人体验基线尚未复测；建议将同一本经常阅读的 PDF 的冷/热 CPU 观察加入下一轮体验反馈。
