# MarginFit 0.1.5 — P0 性能基线与实施协议

日期：2026-10-09。基础版本：正式 0.1.4，Git 基线 5573f94。
目标：为 P1-A/B/C 与 P2-A/B 建立可重复基准；这份报告只记录实测与方法，不包含插件逻辑修改。

## 冻结的基线

- Node 单元测试：36/36。
- Zotero 10.0.6 隔离集成测试：此前 70/70；专项缓存与快速路径：此前 13/13。
- 用户真实反馈：MarginFit 开启时 CPU 20%–25%，约为关闭时两倍；设备、PDF 与放大倍率尚无严谨成对数据，后续不能直接把任何微基准倍率等同于总 CPU 改善。
- Zotero 24 页模拟样本中，原生页宽倍率约 1.17125、内容适配倍率约 2.2665；原生高倍 PDF.js 绘制是额外负载之一。
- 测试原型：tests/performance-baseline.cjs 包含当前 textBox() 与标量候选的相同边界对比，tests/ink-baseline.cjs 包含原 inkBox 与逐像素变体比较。两者均只测 Node 纯计算，且使用合成页面数据。

## 重测结果（单轮，仅参考）

- 100 段 ×100 次：原 textBox 83.18 ms，标量原型 2.37 ms；
- 1,000 段 ×100 次：原 124.72 ms，标量原型 17.01 ms；
- 10,000 段 ×10 次：原 96.22 ms，标量原型 9.08 ms。
- 像素 bbox：body 69.7/69.5 ms、scan 83.5/73.1 ms、isolated page 83.2/59.9 ms、blank 69.5/60.2 ms、dense 133.6/151.3 ms（原版/候选，30 次）。

**解释：** 数值对短时环境/JIT/进程负载敏感，尤其 100 段样本波动很大；仅支持标量算法值得做正式 A/B，不能宣称整个插件 CPU 下降对应比例。所有候选必须在隔离 Zotero 实际调用中确认边界与缩放一致。

## 后续测量规程

每阶段执行测试→Git commit→Git push→重读 v0.1.5 方案，接着下一阶段。新方案 P1-C 包含页码分类，应分别记录 originalBounds、fitBounds、误排正文、边缘候选、扫描 ROI 的开销。

必须按冷/热缓存、原生/智能倍率、ON/OFF 与文档类别分开记录。调度和系统 CPU 用多轮交叉顺序取样，不把功能测试通过声称为总 CPU 改善。失败实验和暂缓项记录下来，不通过的优化不得强行合入。

测试工具只运行在隔离配置；原始用户 Zotero 数据、既有用户未提交诊断脚本、公开 0.1.4 Release 和 updates.json 均保持不变。
