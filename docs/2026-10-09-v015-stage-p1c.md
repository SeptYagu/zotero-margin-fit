# MarginFit 0.1.5 — P1-C 页码与正文边界分离实施记录

日期：2026-10-09。范围：**保守电子 PDF 高置信页码**。混合矢量/扫描/带批注页暂不启用页码自动排除；这是内容安全约束，并非算法遗忘。

## 实现

- 在 P1-A textBox() 同一文字遍历中寻找上/下边缘候选；独立阿拉伯数字、短罗马数字先成为候选；候选 bbox 与正文/脚注必须有明显空间分隔。出现多个边缘候选直接保守拒绝。
- L1 仍严格先测六页，再根据至少四页稳定的“印刷页码 = 物理页序 + 常量偏移”和上下位置模式形成高置信 folioPattern；不足、断号、内容混合或规则突变均不排除。
- 必须是严格 PDF.js OPS 纯文字快速路径、没有批注的页面，才允许候选与正文分离。矢量图、乐谱、图片、扫描页仍以原 raster+text 合并的完整边界适配，不尝试只删文字后让位图重新纳入页码。
- record.raw 始终保存完整原始内容边界；record.folio.body 是不含已确认页码的候选正文框，只有当前页 folio 与 L1 pattern 一致时，Controller.apply 的 scaleDecision 暂时使用正文框，原页 PDF/文本层和批注不修改。
- C.VERSION 升至 3、缓存 STORAGE_VERSION 升至 2。仅保存通过数字与几何合法校验的 folio 元数据（无正文文字）；此前 0.1.4 完整边界缓存不可误用作页码已排除的缓存。
- tests/make-fixtures.cjs：增加 24 页纯文字页码 PDF 与重复 2026 页脚（阴性）PDF。tests/folio.test.cjs：真页码与年份对照、脚注不得被误删、非纯文本拒绝、缓存重开/恶意数据过滤。tests/v014-integration.js：增加待 Zotero 驱动恢复后的实机验证。

## 验证与剩余问题

- Node 单元测试合计 43/43 通过。
- 由独立文档页码产生的 fitRaw 与 fullRaw 区分已通过纯函数验证；页脚重复年份在多个样本中不具备稳定物理页码偏移，不能排除；文本旁有真实脚注时也不排除。
- Zotero headless 调试器目前发生系统图形初始化/调试器 actor 超时，故新功能尚未完成真实阅读器 UI 端到端验证。**不得在发布说明中宣称真实 UI 已通过，更不能启动 GitHub 0.1.5 Release 或更新 feed。**
- 不为扫描件做无 OCR 的不可靠推断：图片独立连通域像页码也可能是乐谱小节编号/编辑标记；未找到误排除为零的可靠证据前坚持保留原算法。
- 后续可对混合 PDF 的既有一次低清 RGBA 分析候选 ROI，但只有在真实样本证明不碰到图表和脚注才可启用。

0.1.4 正式发布版本与自动升级源完全不变；这一阶段仅开发/测试源码。
