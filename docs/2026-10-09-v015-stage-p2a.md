# MarginFit 0.1.5 — P2-A 缓存增量与并发写入

日期：2026-10-09。目标：逐页检测时不再重建整个 PDF 的缓存快照。

- Session.read() 优先调用 Store.schedulePage(p,record)；每页仅进行常数级验证与 dirty Map 更新。
- flush() 到来时才读取/合并/序列化全部缓存；同一 PDF 的多 Reader 共用模块级 WRITE_QUEUE，保证读→合并→写操作依次执行，避免同步改写丢失记录。
- 持续检测时仍沿用 1.2 秒 debounce；每页可复用老缓存，dirty 按页号去重；写入前将最新页置于末尾，最多保存最近 3,000 条。其余失效规则沿用 P1-C 升级后的 schema。
- session close 触发 dirty flush，不阻塞 PDF 阅读器卸载。写盘异常由 close/调度捕获，下次无法载入则重新检测；不改原始 PDF。
- 为原 Map.schedule() 保留测试兼容入口，但正常检测热路径不再调用该全量入口。

验证：npm test 46/46 通过。新增 1000 页更新在 flush 前零次全量 pack、flush 后一次 pack；两个阅读器的并发写入合并保留两个页面；3100 页情况下保留最近 3000 条。

剩余风险：IOUtils.writeJSON 的 crash-atomic 替换尚未在目标 Zotero 的 I/O 接口上验证，没有启用未经验证的 tmpPath 选项；崩溃造成单一 JSON 损坏时只能安全回退重新检测。全局长期缓存清理尚无数据证明必要，未实施。

Zotero headless 集成仍存在调试器启动故障，**此阶段未获得完整真实 UI 回归**。正式 0.1.4 Release 与 updates.json 不变。
