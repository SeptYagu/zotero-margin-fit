# MarginFit 0.1.5 — P2-B 连续滚动时的页面几何查询优化

日期：2026-10-09。

- runtime.Controller.input() 之前是每 75ms 固定节流检查主要可见页，在连续滚动过程依然调用 page() 约每 75ms。
- 现改为 75ms **尾沿合并（trailing debounce）**：wheel+scroll+touchmove 持续发生时只作 epoch 失效、最后输入时间更新与定时器重排，不查询任何页面 DOM 几何。停止输入约 75ms 后才检查一次主要可见页，再执行原 500ms idle-refine 规则。
- 快速失效、L1/L2 让路、5% 死区、缩放锚点、关闭开关和销毁清理都保留。
- tests/controller.test.cjs 新增 12 次、每 19ms 连续滚动的模拟：期间 page() 次数严格 0；停止后等 110ms，恰好一次。
- 未对每 500ms 阅读器发现轮询做未经实际收益验证的重构；UI 连续滚动结束时识别页面只增加至多一个尾沿周期的延后，不影响停止后对稳定页的检查。

验证：npm test 47/47 通过。Zotero headless 集成因测试调试器启动超时未获确认，阶段任务不代表真实 Zotero CPU 总量下降了固定百分比。0.1.4 Release / updates.json 不改。
