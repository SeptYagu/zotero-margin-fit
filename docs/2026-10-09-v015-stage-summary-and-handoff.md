## 核心安全与性能结论

1. P1-A 的文字边界算法不改变有效 bounding box；等价试验 10,000 组通过。合成微基准显示几倍的单函数加速，但这不是系统 CPU 降幅。
2. P1-B 不做缺乏数据支持的复杂模型分类。所有有绘图、乐谱、扫描或未知操作的页面仍走原保守检测。
3. P1-C 只排除**至少四个 L1 样本跨页规律一致、位置独立、同一实际页面明确为无批注的纯文字内容**的页码。正文、图表、脚注、混合矢量、扫描件不因为“数字”被误裁；保留 full raw，只有拟合时使用 body raw。原 PDF 的页码始终存在。缓存只保留已验证的 bbox 与编号元数据，不储存正文文字。
4. P2-A 在合成 1,000 页的缓存更新过程中每次检测不再全量 pack，仅 flush 时批量打包。并行写入合并及最多 3,000 页的容量测试均通过。
5. P2-B 的 12 次连续模拟输入在滚动中产生 0 次 page() DOM 读取，尾沿停稳后仅 1 次；原固定 75ms 调度相较可触发周期读取。真实 Zotero 滚动帧率尚待测。

## 发行阻断、未实施与下一步

**本版不得发布，直至真实 Zotero 集成与用户体验验收通过。** 测试驱动恢复后运行：
- npm test；
- npm run test:integration（原 70 检查）；
- npm run test:cache（新增纯文字页码及年份阴性用例）；
- 长篇 PDF 相同缩放倍率下 ON/OFF、0.1.4/0.1.5、冷/热缓存 CPU + 掉帧对照；
- 检查页码场景、乐谱、扫描、脚注、矢量、批注、分屏、独立阅读器及旋转。

保留的实验方向：扫描/混合页的“只剔除页码区域”安全 ROI 还没有充分可靠证据，暂不启用；原生 PDF.js 高倍页面渲染开销也不在本版优化范围。P1-B 更激进的 raster-first 文档预测需要真实长文档 A/B 数据才能重启。

现阶段把插件视为功能完整但尚未实机验收的 **v0.1.5 候选开发版**；后续在恢复隔离 Zotero 后继续，不需重新设计需求或询问已确定的优先级。
