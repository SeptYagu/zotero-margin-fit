# v0.1.15 ? Restore all-open PDF indexing

The user originally required: complete current active PDF first, then automatically finish every other still-open PDF, one cooperative background worker. v0.1.14 incorrectly stopped once the active PDF was done. This was not an authorized product change.

## Native diagnosis

On Zotero 10.0.6, after restoring simple inactive-PDF scheduling, an inactive 24-page PDF advanced from 8 to 16 cached pages and then the one worker remained busy, unable to finish. The problem is render scheduling, not the inability to read a hidden PDF: direct hidden page getPage, getTextContent and getOperatorList completed; an isolated session read did complete.

PDF.js display-intent raster work can use requestAnimationFrame from a hidden reader iframe, which may suspend indefinitely. A **background-only** print-intent render bypasses requestAnimationFrame. Foreground display still uses native display-intent rendering, original viewport and current zoom.

## Results: true all-open completion

- Native test with selected one-page B and hidden 24-page A: B cached 1/1 first. Without activating A, idle scanner cached A to 24/24. The sole worker stopped only when both PDFs were complete.
- Native test with active 24-page B: A did not scan during B; after B reached 24/24, A automatically gained page records even while B remained selected.
- A second test with both Fit Width and Fit Height OFF showed Detect Margins ON still schedules caching, with no automatic zoom/scroll writes. Detect Margins OFF stops it.
- A background print/display paired image test showed identical hashes for six non-annotated synthetic pages, including pages 16/17 where hidden scans previously stalled.
- Display-only annotation control intentionally differed between print and display image render (print omits that annotation). Corrected background print detection unions the annotation's displayed PDF.js rectangles in viewport coordinates. A native annotated PDF generated by tests/make-fixtures.cjs produced reliable non-fullpage detected bounds agreeing with the foreground display scan within 3 PDF units. Malformed annotation rectangles cause a safe fullpage fallback.
- Real user PDF data and the user's production Zotero configuration were not touched; all checks ran on disposable profiles and generated fixtures.

## Algorithm

- Detect Margins is the independent master for scanning; Fit Width/Height/OFF controls only viewport fitting.
- Select active eligible reader first. If complete, preserve the previous eligible background target to avoid churn; otherwise take the next open incomplete PDF in reader order. Closed readers and paused sessions are skipped.
- Only one background worker and one in-flight scan at a time; active user selection preempts other scans and renders. No new timers, PDF migrations, concurrent windows, or layout changes.
- PDF.js render intent is display when there is no background token and print only for background offscreen detection. Background print records preserve display-only annotations by conservative geometric union.

Caveat: unusual PDF optional-content configurations may have print/display differences not represented by the generated fixtures. These should retain conservative geometry if encountered.
